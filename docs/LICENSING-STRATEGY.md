# Licensing and collaboration strategy (decision required)

There is deliberately **no LICENSE** file in this starter. A public GitHub repository without a license does not grant the public the right to redistribute or commercially use its contents by default.

Choose and add a software license **before** inviting open-source use:
- MIT: maximum adoption, also allows unmodified commercial forks.
- AGPL-3.0: network-copyleft obligations can help sustain a commercial hosted offering, with tradeoffs for contributors and enterprise adoption.
- Dual-license/open-core: a community license plus separately licensed commercial use is possible if you hold the required rights for the code and all contributors agree to terms.

Separate four kinds of rights: **your software**, **Reddit data and author stories**, **TTS model/voice checkpoints and libraries**, and **visual/audio assets**. Software licensing cannot grant rights to content sourced elsewhere. Model weights and dependencies can have different conditions even if the app code is open source. Have counsel review your plan before signing reseller deals.

Commercial options: paid hosted creator workspaces; private deployments and support; agency/white-label licensing; early design-partner engagements. Never promise an end-user ownership of Reddit or YouTube data that you do not have.
